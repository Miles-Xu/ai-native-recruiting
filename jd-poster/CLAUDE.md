# JD 海报

将 JD 排成可分享的 PNG。现有实现是 HTML 模板加 Playwright 截图；默认导出 3 倍像素图，可按品牌和发布渠道调整版式。

## 准备

确认 JD、品牌、工作地点和投递方式。仓库中的 `jd_poster.html` 和 `examples/` 是现有范本，不自动代表本次招聘信息。

环境准备见 [根目录 README](../README.md)。以下命令从仓库根目录执行，Windows 将 `./run` 换成 `.\run.cmd`。先执行 `./run doctor --browser`，确认 Chromium 能实际运行；缺浏览器时执行一次 `./run setup-browser`。脚本直接打开本地 HTML，也接受 HTTP(S) URL，不依赖固定端口。

## 填写内容

为本次海报在 `_tmp/` 中建立 HTML 副本，保留公共模板供后续使用。需要更新公共样式时再修改 `jd_poster.html`。

- 保留岗位职责、要求和投递条件的含义；可以调整标点、分段和重复表述。压缩或改写实质条件时，与用户确认。
- 常规岗位可用“职责 / 要求 / 加分项”；多个并列方向可沿用 `.lane` 结构，不要求每份 JD 都套同样的模块。
- 替换或确认 Logo、配色、标题、地点、邮箱和页脚文字。装饰与标语按品牌需要取舍。

## 检查排版并出图

可先沿用模板宽度。内容出现明显碎行、过长或溢出时，用脚本比较几个宽度：

```bash
./run widths "jd-poster/_tmp/岗位.html" 380,400,420,440,460,480
```

脚本输出标题行数、短尾数量和末行填充率。短尾指多行文本的末行填充率低于 30%，用于提示可能需要调整的位置，不是验收门槛。宽度选择还要考虑阅读字号、整图长度和发布渠道。

确定宽度后出图：

```bash
./run poster "jd-poster/_tmp/岗位.html" 440 "jd-poster/_tmp/岗位.png"
```

脚本会临时覆盖 `body` 宽度，不修改输入 HTML。需要让 HTML 预览与 PNG 一致时，再同步 HTML 的 viewport 和 `body` 宽度。

长标题可以合理换行；不要为了凑一行把字号缩得难以阅读。脚本的主标题行数统计针对现有模板中 `h1` 的首个文本节点，改过标题结构后需以页面实际显示为准。

## 交付检查

- JD 内容完整准确，品牌和投递信息已确认。
- 标题、正文和联系方式可读，没有裁切、重叠或水平溢出。`scrollW` 大于设定宽度时检查溢出原因。
- 查看实际 PNG，确认换行自然、底部留白合适。必要时调整宽度、间距、分段，或拆成多张。
- 默认在 `_tmp/` 保存本次 HTML 和 PNG；用户指定其他位置时使用指定位置。`examples/` 用于维护可公开的范本。
- 浏览器因权限或沙箱限制无法启动时，保留 HTML 并说明 PNG 尚未生成；不要反复安装 Python 或把模板文件当成图片交付。有可用的浏览器预览时可以检查 HTML，但预览成功不等于导出成功。

## 文件

- `jd_poster.html`：公共模板
- `scripts/sweep_width.py`：比较多个宽度的换行情况
- `scripts/render_poster.py`：生成 PNG 并打印排版诊断
- `examples/`：现有海报范本
