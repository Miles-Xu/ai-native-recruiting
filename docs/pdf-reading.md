# PDF 读取路径

这份说明用于任何需要读取 PDF 的任务，尤其是简历筛选。先完成读取和核对，再判断岗位；每次换模型或 agent 仍走同一条路径。

## 运行环境

在仓库根目录使用 `./run`（macOS / Linux）或 `.\run.cmd`（Windows）。入口通过 uv 选择项目的 Python 3.12 和 `uv.lock` 中的依赖，缓存和虚拟环境放在本仓库。无需激活环境，也不要改用系统 `python3`、`py -3.12` 或全局 pip 来碰运气。

第一次先执行：

```bash
./run doctor
./run setup-ocr
```

`setup-ocr` 下载固定版本并校验哈希的英文、简体中文识别数据，供 PyMuPDF 内置 OCR 使用，不需要另装 Tesseract 程序。识别在本机进行，不上传简历。需要联网的只是首次环境和语言包准备。

## 读取并核对

```bash
./run pdf "resume-screening/examples/resume_王五.pdf"
```

命令返回一个独立的产物目录，默认放在 `resume-screening/_tmp/`。也可用 `--out-dir "resume-screening/_tmp/本次记录"` 指定空目录。输入路径相对于当前执行目录；文件名有空格、中文或特殊符号时加引号。

目录包含：

- `report.json`：总页数、每页状态、文本来源、警告和需要人工核对的页码
- `text.txt`：按页标记的文本，便于全文阅读和引用
- `page-001.png` 等：每一页的渲染图，供核对版面和关键字段

先读报告，确认页数齐全；再读全文并查看所有页面图片。双栏、表格、页眉页脚可能影响文本顺序，姓名、公司、日期、薪资和项目指标尤其需要对照原图。脚本成功不代表这些事实已由人核实。

## 不同 PDF 的处理

| 情况 | 脚本行为 | 下一步 |
|------|----------|--------|
| 正常文本 PDF | 提取文本层，并渲染全部页面 | 对照页面核对阅读顺序和关键字段 |
| 扫描件、文本很少或乱码 | 默认逐页尝试全页 OCR | 检查 OCR 警告和原图，尤其是人名、时间和数字 |
| 可选文本中夹着图片 | 保留可选文本，对图片区域执行 OCR，不按图片面积忽略内容 | 核对图片里的经历、联系方式等；图片可能只是照片，也可能包含正文 |
| 缺少 OCR 语言包 | 保存已有文本和图片，报告未解决页 | 执行一次 `setup-ocr`，然后用新目录重跑 |
| 扫描和文本混合 | 每页单独判断和记录来源 | 不因某一页可读就认定整份已读完 |
| 加密 PDF | 返回退出码 4，不尝试猜密码 | 用户提供密码后，以 `--password-env` 指定存放密码的环境变量 |
| 损坏文件、不是 PDF、路径不存在 | 返回明确错误 | 检查输入，不反复更换解析库 |
| 空白或仍无法识别的页面 | 保留图片，报告未解决页 | 查看原图；确认为空白时记录依据，确有缺失时请求可读材料 |

自动检测是启发式的，不能证明文本层完整。原图有内容而文本缺失时，可执行 `./run pdf "文件.pdf" --ocr force` 全页识别；`--ocr off` 只用于诊断，不能据此忽略扫描页。

默认识别语言为 `eng+chi_sim`。其他语言可通过 `--language` 和 `--tessdata` 指定已准备好的语言数据；缺语言数据不计作识别成功。

## 退出状态

| 退出码 | 含义 |
|--------|------|
| 0 | 全部页面已提取文本，状态为 `ready_for_review`，仍需对照原图 |
| 2 | 输入或运行错误，按错误信息处理 |
| 3 | 有页面需要核对，状态为 `needs_review`；可以查看已有产物，但不能声称已完整读取 |
| 4 | 密码缺失或不正确 |
| 5 | 当前 Python 缺少 PyMuPDF，应回到仓库入口 |

已有非空产物目录不会被覆盖。报告不存在、页数不全或页面未解决时，不把空文本、零字符输出或局部内容用于完整筛选结论。
