# 字段提取

以下字段用于整理信息，不要求所有转写都具备。姓名冲突、说话人归属和事实依据按 [SKILL.md](../SKILL.md) 处理。

## 面试纪要

| 内容 | 提取范围 |
|------|----------|
| 姓名 | 用户确认的写法，或无冲突的标题、自我介绍；无法确定时标记待确认 |
| 当前情况 | 明确提到的在职状态、公司、团队、角色 |
| 地点 | 当前城市、期望地点、远程偏好 |
| 背景 | 技术领域、项目、教育、工作年限 |
| 薪资 | 明确说出的现有薪资、期望和组成，分别记录 |
| 流程 | 正在沟通的公司、轮次、offer 和答复期限 |
| 安排 | 可约时间、到岗时间、后续沟通事项 |
| 动机 | 候选人明确陈述的看机会原因与关注点 |

信息充分时，`recommendation[]` 用五项摘要便于转发：目前状态、目前&期望地点、基本情况（含已明确的职级）、当前流程、看机会原因。这里保存客观沟通摘要，不额外做推荐判断。

字段各有侧重，避免重复。缺失项写“未明确提及”；如果大部分信息缺失，可以省略摘要表，在 `sections[]` 中列已知内容和待确认项。

流程中已有 offer、终面或答复期限时，可用 `⚠️` 提示关注。只写原文给出的数量、公司和日期；到终面不等于已有 offer，也不自动代表时间紧迫。

## 技术、产品及通用会议

按实际内容组织 `sections[]`，可包括：

- 讨论的问题、背景与约束
- 已确认的决定，以及讨论过但未采纳或未定的方案
- 待办、负责人和时间；后两项未明确时标注待确认
- 尚未解决的问题

这些会议不套用候选人摘要表，`recommendation` 可为空数组。

## 信息不足

能提取部分事实时生成简版。只有标题、寒暄，或多人混讲且无法确认主要内容时，说明现有材料不足及需要补充的内容。

是否使用简版取决于信息能否支持有用的纪要，不按缺失字段的固定比例判断。
