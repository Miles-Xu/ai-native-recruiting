# HTML 纪要质量

默认使用 `scripts/render_minutes.py` 渲染，样式在脚本中维护。以下描述现有模板；用户有明确版式要求时可调整。

## 页面结构

| JSON 字段 | 页面内容 |
|-----------|----------|
| `title` / `subtitle` | 纪要标题与补充信息 |
| `kpi[]` | 关键事实摘要，通常不超过四项 |
| `sections[]` | 编号小节和要点 |
| `recommendation[]` | 面试沟通摘要，页面标题为“沟通摘要” |
| `generated_at` / `source` | 生成时间与来源 |
| 转写文件 | 底部可展开的原文 |

数组为空时，脚本省略对应区块。小节数量按内容确定；信息不足和非面试纪要不需要填满候选人字段。

## 配色

| `tone` | 用途 |
|--------|------|
| `blue` | 当前情况等关键事实 |
| `green` | 已完成或已确认的事项 |
| `orange` | 待跟进的进展 |
| `red` | 原文明确的紧急事项 |
| `purple` | 可约时间等补充强调 |
| `indigo` | 默认主色 |
| `grey` | 注脚 |

颜色用于区分状态，不借颜色暗示对候选人的评价。`recommendation[].value` 含 `⚠` 时，现有模板会高亮该行。

## 内容和显示检查

- 重点信息容易找到，正文不逐句重复转写。
- 数字和时间保持原文精度，例如“二十几 K”不改成“20K+”，“周五晚上”不补具体钟点。
- 不用标题中的姓名填充摘要项，不在页面中加入模型的执行说明。
- 页面中文正常，文本和表格无截断或重叠；长内容和窄窗口下也能阅读。
- 传入转写时，原文区可展开并显示对应记录。
- HTML、JSON 和转写保存齐全；用户选择其他交付方式时，按该方式检查。
