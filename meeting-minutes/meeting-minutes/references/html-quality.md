# HTML 纪要质量规范(商务报告风)

本规范描述 `scripts/render_minutes.py` 产出的商务报告风 HTML 应满足的内容与排版要求。
样式由脚本统一持有(CSS 写在脚本里),Claude 只产出结构化 JSON,无需手写 HTML/CSS。

## 结构骨架(对应 structured JSON)

1. **双线 Header**:`title`(如「面试纪要 · 姓名」)+ `subtitle`(如「岗位 | 当前公司」)。顶部实线 + 底部双线,主色 indigo。
2. **KPI 横条**:`kpi[]`,4 项以内,每项 `{label, value, tone}`。只放决策信息,语义色区分。
3. **编号小节**:`sections[]`,每个 `{title, bullets[]}`,渲染成「1. / 2. / 3.」编号 + bullet。
4. **推荐评语块**:`recommendation[]`,5 字段表格;`value` 含 `⚠` 的行自动高亮(橙底)。
5. **页脚**:生成时间 + 来源(本地会议转写)。
6. **折叠原文区**:`<details>`,内嵌完整 `transcript`,默认折叠,供回查。

## 语义色(tone → 用途)

| tone | 色值 | 用途 |
|------|------|------|
| `green` | #2e7d32 | 成功 / 强正面 / 高质量(如总包、积极意向) |
| `orange` | #b26a00 | 待定 / 进行中 / 需关注(如进度、⚠️ 竞争) |
| `red` | #c62828 | 警告 / 风险 / 紧急 |
| `blue` | #1565c0 | 高价值信息 / 关键状态(如当前公司) |
| `purple` | #6a1b9a | 次要强调(如可约时间、轮次) |
| `indigo` | #283593 | 主色(header / 编号 / 推荐评语条),默认 tone |
| `grey` | #6b7280 | 低优先级 / 注脚 |

KPI 每项按含义选 tone,不要乱配色(颜色表达状态)。

## KPI 取舍规则

只放对决策有用的信息。优先:
- 薪资 / 总包
- 当前公司 / 职级
- 晋升节奏 / 成长信号
- 流程阶段 / offer 状态
- 可约时间 / 关键风险

数字化分寸:
- 原文支持时才用数字(`月 base 20K+` 优于 `二十几K`;`2年9个月 / 3+1轮 / 55W` 优于含糊散文)
- 原文模糊就保留原粒度(`周五晚上` 不要硬编成具体钟点)
- 不为显得精确而瞎猜

避免:
- KPI 重复标题已出现的姓名
- 弱填充事实
- 不可验证的猜测

## 推荐评语 5 字段(必出)

目前状态 / 目前&期望地点 / 基本情况(含职级) / 当前流程 / 看机会原因。

- 字段间不重复(职级写在基本情况里,其他字段不再提)
- 当前流程靠后阶段加 `⚠️` + offer 数量 + deadline → 自动触发高亮行
- 不做风险主观判断(不写「稳定性差 / 跳槽频繁 / 建议观望」),只呈现原文客观细节
- 即使某字段为「未明确提及」也要列出,不可整段跳过

## HR 视角内容规则

- 只呈现 HR 此刻需要的事实、进度、时间、风险
- 不暴露内部护栏话术(不写「不做脑补 / 文档未明确所以不写」)
- 事实不清就省略或用干净的窄区间表达
- 电话沟通 / 信息交换场景:当成信息交换笔记,不逐句复述,只留决策有用的事实(职级、成长、动机、当前 scope、流程、时间、风险)
- 短 bullet 优先,不写大段流水账

## 质量验收

好的纪要 HTML:
- 信息密度高、视觉稳定、5~10 秒可扫读
- 语义配色正确、跨纪要风格一致
- 面向 HR 决策书写,不是 agent 自述

坏的迹象:
- 一坨文字墙
- 配色乱、无语义
- KPI 重复标题信息
- 结构合法但视觉塌
- 把元话术直接展示给 HR
