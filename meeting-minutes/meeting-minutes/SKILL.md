# 纪要整理

从转写中提取事实、结论和待办，按会议主题组织。默认用脚本生成 HTML 供阅读和归档；用户指定纯文本、只提取某一部分或其他格式时，以本次要求为准。

## 信息依据

- 每份记录以本次提供的转写为依据。用户明确要求结合简历或其他资料时，区分各来源，不能把补充材料写成会上说过的话。
- 人名、公司、角色、薪资和看机会原因等关键字段，逐项回查原文。缺失时写“未明确提及”；模糊的数字和时间保留原有精度。
- 区分候选人陈述、访谈方介绍和会议结论。访谈方介绍的岗位优势不代表候选人认可；正在面试的公司不代表当前雇主。
- 姓名优先采用用户明确确认的写法。文件名、标题和正文存在冲突时标记待确认，不用其中一项直接覆盖其他来源。
- 不从履历、职级或语气推断薪资、意愿、性格和稳定性。原文包含评价时，注明是谁的判断。
- 批量处理时，为每份输入建立独立的结构化数据和归档目录，检查关键字段是否来自对应原文。同名公司或角色本身不代表信息混入。

## 整理内容

通读转写后，按主要讨论内容选择 `interview`、`technical`、`product` 或 `general`，不因偶然出现一个关键词就切换类型。

提取字段时读取 [references/field-extraction.md](references/field-extraction.md)：面试关注背景、意向、流程和时间；其他会议关注议题、结论、待办及未解决的问题。

内容不足时按已有信息输出简版，说明缺少的关键内容。只有标题或寒暄时，说明信息不足，不填充空表或虚构结论。

## 默认 HTML 交付

1. 按 [references/artifact-schema.md](references/artifact-schema.md) 组装 JSON，原样保留转写文件。
2. 用 [scripts/render_minutes.py](scripts/render_minutes.py) 生成纪要。本仓库通过根目录的统一入口执行，输入路径按实际文件替换：

   ```bash
   ./run minutes --structured "meeting-minutes/_tmp/记录.json" --transcript "meeting-minutes/_tmp/记录.txt"
   ```

   Windows 使用 `.\run.cmd`。输入路径相对于执行目录，也可传绝对路径；可用 `--out-dir` 指定归档位置。若将本技能独立复制到其他项目，渲染脚本仅用 Python 标准库，应接入目标项目已配置的 Python 环境。

3. 检查归档中的 `纪要.html`、`structured.json` 和 `transcript.txt`，确认内容一致。默认归档日期是当天，同名目录追加序号；可用 `--date` 指定归档日期。
4. 按 [references/html-quality.md](references/html-quality.md) 查看生成页面，确认中文、表格和原文折叠区正常。

脚本也支持不传 `--transcript`，此时仅生成 HTML 和 JSON，不算已归档原文。渲染失败时说明失败点和已完成的部分，修复后再提供成品链接。

## 交付检查

- 姓名、公司、角色、薪资、流程和动机与各自来源一致。
- 信息充分的面试纪要包含五项沟通摘要；简版或非面试纪要按实际内容组织。
- 正文呈现讨论内容，不写“已防止脑补”“已完成闭环”等执行说明。
- 保存位置、文件格式与用户要求一致。发现事实错误时更正并指出受影响内容，重新生成对应文件。
