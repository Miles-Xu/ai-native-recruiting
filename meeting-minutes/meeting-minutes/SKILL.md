# Meeting Minutes Generator(本地 HTML 版)

> 路径:`meeting-minutes/SKILL.md`
> 版本:2.0(本地 HTML 版:商务报告风 HTML + 本地三件套落盘)

## Package Layout

- `SKILL.md`:主流程、触发条件、分流与验收
- `references/html-quality.md`:商务报告风 HTML 排版规范(语义色、布局、质量验收)
- `references/field-extraction.md`:字段抽取与降级规则
- `references/artifact-schema.md`:structured JSON 落盘规范(给后续看板/程序读取)
- `examples/interview-minutes.html`:面试纪要 HTML 示例(脚本真实渲染产物)
- `examples/info-insufficient.html`:信息不足降级示例
- `scripts/render_minutes.py`:把 structured JSON 渲成 HTML 并原子落盘三件套

## 🔴 HARD Rules(优先级高于一切)

1. **只写转写明确出现的信息**--人名/公司/数字/流程/时间点,必须有转写原文支撑
2. **禁止脑补**--面试官名字、对标公司、候选人意图排序、未陈述的结论
3. **文档隔离**--每份转写独立处理。本地化后每个会议在独立 Claude 窗口处理,天然隔离;若一个窗口内连续处理多份,每份清零 context,串行完成(渲染+落盘)再处理下一份
4. **信息不足时宁缺毋滥**--缺字段就写"未明确提及",不要补完句子
5. **产物是商务报告风 HTML**--通过 `scripts/render_minutes.py` 渲染,不要只在聊天里回一段纯文本就算完成
6. **发现虚构信息→立即重渲修正版**--标题末尾标注【修正版】
7. **多说话人混乱时先降级**--先提炼"确定事实",不要伪造完整时间线

## Trigger Conditions

以下任一命中,就激活本 skill,而不是普通文本总结:

- 用户粘贴会议/面试转写文本 + "做个纪要"/"面试纪要"/"会议记录"/"总结下"/"整理一下"
- 用户直接贴进来一大段明显是录音转写的对话文本
- 当前任务产物明显面向回看/归档/转发给业务方,而不是仅做一次性口头答复

### Trigger Guardrail

若任务满足本 skill 触发条件:

- **默认产物必须是商务报告风 HTML**(经 `render_minutes.py` 落盘)
- **禁止只回当前聊天一段纯文本就算完成**
- **除非用户明确说"别落盘 / 只在这里文本给我"**,否则不得降级成纯文本交付
- 若渲染/落盘失败,必须说明失败点并修复,不能拿纯文本冒充闭环

## Closed-loop Workflow

### Step 1: 读取转写

用户直接粘贴转写文本(或给出本目录下的转写文件路径)。把原文原样保留,后续要落盘成 `transcript.txt`。

### Step 2: 文档健康检查

判断这份转写是否适合直接出纪要:

- **可正常处理**:有连续对话/段落,主题集中,可识别人名/岗位/讨论主题
- **可降级处理**:转写零碎、多人混讲、字段不全,但仍能提炼部分确定事实
- **不适合直接处理**:只有标题、只有几句寒暄、明显不是转写、内容严重截断 → 不要硬生成完整纪要,改出"信息不足"卡片或先向用户说明

### Step 3: 分类

| Type | Signals |
|------|---------|
| **interview** | 候选人/面试/简历/薪资/offer/base |
| **technical** | 方案/架构/设计/性能/trade-off |
| **product** | 需求/PRD/优先级/排期/用户 |
| **general** | 通用讨论 |

优先级:interview > technical > product > general

### Step 4: 提取字段

按类型提取,**只从当前转写提取,绝不跨文档引用**。
字段清单、抽取硬规则、缺失字段降级规则:读取 `references/field-extraction.md`。

### Step 5: 组装结构化 JSON

把提取结果组装成 structured JSON(形状见 `references/artifact-schema.md`):
- `title` / `subtitle` / `kpi[]`(4 项以内,每项带 `tone` 语义色) / `sections[]` / `recommendation[]`(推荐评语 5 字段) / `source`
- 排版与字段要求见 `references/html-quality.md`

#### Step 5.1: 防窜校验(HARD — 落盘前强制)

落盘前对以下 5 个关键字段逐一在原文中回溯查找支撑:

| 字段 | 验证方法 | 无原文支撑时 |
|------|---------|------------|
| **公司名** | 原文是否出现该名称 | 写「未明确提及」 |
| **角色/title** | 原文是否描述该岗位 | 写原文原话,不脑补 title |
| **薪资/总包** | 原文是否有明确数字 | 写「未明确提及」,不猜区间 |
| **工作经历** | 原文是否提到过往公司 | 没有就不写 |
| **看机会原因** | 原文是否陈述动机 | 写「未明确提及」 |

竞争公司 vs 当前公司消歧:
- 当前在职公司必须有明确归属信号(如「我现在在 XX 做的」)
- 正在面的公司标为竞争/流程信息,不可写入「当前」字段
- 无法区分时宁可写「未明确提及」

若一个窗口内批量处理 ≥2 份转写:每份的公司/角色/经历/动机存为指纹,与已生成的比对;命中但当前原文无支撑 → 判定窜信息,移除替换为「未明确提及」。

额外硬规则(HR 视角):
- **说话人归属(HARD)**:HR(访谈方)说的观点/介绍/卖点不得写成候选人认同或期待;HR 抛的信息只能标注为「HR 介绍/同步」
- **推荐评语段(HARD)**:每份纪要末尾必出推荐评语(5 字段:目前状态 / 目前&期望地点 / 基本情况(含职级) / 当前流程 / 看机会原因)。当前流程靠后阶段加 ⚠️ + offer 数量 + deadline。**字段间不重复**;**不做风险主观判断**(不写「稳定性差/建议观望」)
- **不写元话术**:HTML 里不要出现"未脑补 / 文档未明确所以不写"这类系统自述
- **原文支持时再数字化**:薪资/年限/轮次/可约时间/流程阶段,只在原文明确或支持窄区间时才转数字
- **短句优先**:正文 bullet 化,不写流水账

#### 输出分档

- **A. 完整纪要**:信息充分,KPI + 背景 + 当前进程 + 备注 + 推荐评语
- **B. 简版纪要**:字段不全但核心事实可提炼,section 缩成 背景 / 已知进展 / 待确认项
- **C. 信息不足**:标题标「纪要生成失败 / 信息不足」,只写哪些信息不足、为什么不能安全生成、建议补什么

### Step 6: 渲染 + 落盘三件套(HARD — 不可跳步)

把 structured JSON 写到临时文件(如 `_tmp/<候选人>.json`),把原文写到临时文件,然后调脚本渲染落盘:

```bash
py -3.12 meeting-minutes/scripts/render_minutes.py --structured <临时json> --transcript <原文文件>
```

脚本会在 `纪要档案/<YYYY-MM-DD>_<候选人>/` 下落:
1. `纪要.html` — 商务报告风成品(自包含,可双击打开)
2. `structured.json` — 结构化数据(补齐 date/generated_at)
3. `transcript.txt` — 原始转写

**三件齐全才算完成。** 脚本自带防覆盖(同名目录追加 `-2`/`-3`)。

#### 6.0 落盘前自检

- 命中了 meeting-minutes 触发条件
- 最终交付物是 HTML(经脚本落盘),不是聊天里的纯文本
- 已通过 Step 5.1 防窜校验:5 字段有原文支撑;批量模式已做跨文档比对
- 三件套都已落盘到 `纪要档案/<日期>_<候选人>/`
- 准备好在失败时返回"失败原因 + 下一步",不静默降级

### Step 7: 验收信号

闭环验收:
- 已实际生成 HTML 并落盘三件套,不是只产了 JSON / 文本草稿
- 没有偷偷降级成纯文本回复

内容验收:
- **事实一致**:HTML 中姓名/公司/薪资/轮次能在原文找到依据
- **无脑补**:不存在原文没出现却被写进 HTML 的实体/结论
- **推荐评语完整**:5 字段全列(即使部分为「未明确提及」)
- **异常已降级**:信息不足时走简版或信息不足卡片
- **文档隔离成功**:本次无上一份候选人的残留信息

质量验收(读 `references/html-quality.md`):
- 视觉层级清楚(header / KPI / 编号小节 / 推荐评语 / 页脚)
- 语义配色正确;可 5~10 秒扫读;中文不乱码;浏览器可正常打开

若任一项不满足:先修正再落盘;已落错版立刻重渲修正版。

## 常见错误速查

| 问题 | 原因 | 修复 |
|------|------|------|
| HTML 中文乱码 | 写文件没用 UTF-8 | 脚本已强制 UTF-8 无 BOM;别用 PowerShell `Out-File` 覆写 |
| context bleed | 上一份转写信息带进下一份 | 每份独立处理,清零 context;批量串行 |
| 跨文档窜字段(公司/经历/角色) | 模型用前序候选人信息填充当前空字段 | Step 5.1 五字段回溯 + 跨文档比对 |
| 竞争公司写成当前公司 | 混淆"正在面"与"当前在职" | 找明确归属信号,无则写「未明确提及」 |
| HTML"很完整"但事实不实 | 模型补全倾向过强 | 缺字段写「未明确提及」,降级输出 |
| 转写只有碎片句子 | 强行套完整纪要模板 | 改走简版或信息不足卡片 |
| 只在聊天回了纯文本 | 没激活本 skill 或偷降级 | 回到本 skill,补做 HTML 渲染+落盘闭环 |
