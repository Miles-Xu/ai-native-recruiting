# examples/ — 完整示例

两组「输入简历 → 筛选结论」的对照，用来看这套 SOP 实际跑出来是什么效果。

| 输入 | 产物 | 结论 | 看点 |
|------|------|------|------|
| `resume_李四.pdf` | `screening_李四.md` | ⭐ 强推荐 | "好"长什么样：预训练直接证据成表、细分方向归类、造轮子/主导程度判断、开源核验方法、追问到能顶住的 pre-talk 清单 |
| `resume_王五.pdf` | `screening_王五.md` | ✅ 推荐（但排除了高 bar 岗） | **关键词≠够格**：简历堆满 Megatron/DeepSpeed/NCCL/CUDA/千卡/100B MoE，核验后判定训练侧全是"用轮子"，排除 JOB-101，重新落到真正匹配的 JOB-103 |

两份产物都是把 PDF 路径甩给按上级 `CLAUDE.md` 配置的 Claude Code 后、它自己跑出来的原始输出，只删掉了给 SOP 维护者看的执行备注。没有人工润色——包括结论里那些"简历未提供""需 pre-talk 补证"的地方，那正是 SOP 要求的宁缺毋滥。

## 全部为虚构数据

候选人（李四、王五）、公司（星枢智能、云澜科技、鲸跃云）、学校（华清大学、南江大学）均不存在，简历用 HTML 手写后转 PDF 生成。岗位编号 JOB-1xx 和用人经理（陈默、吴桐等）同为虚构，见仓库根 `README.md` 的虚构声明。

## 自己复现

```bash
cd resume-screening
claude
> examples/resume_王五.pdf
```

产物不会与这里的示例逐字相同（模型输出有随机性），但结论方向、必须出现的字段、以及对"用轮子"的识别应当一致——如果不一致，通常是 SOP 里某处口径写得不够硬，值得改。
