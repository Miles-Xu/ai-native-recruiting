# 简历筛选示例

两组虚构的“简历 PDF → 筛选结论”，用于说明如何结合岗位口径和项目证据进行初筛。

| 输入 | 结论 | 主要内容 |
|------|------|----------|
| [李四简历](resume_李四.pdf) | [筛选结论](screening_李四.md) | 项目证据、主次方向、个人贡献与开源待核验项 |
| [王五简历](resume_王五.pdf) | [筛选结论](screening_王五.md) | 区分不同研发职责，解释岗位匹配依据 |

候选人、公司、学校、岗位联系人均为虚构。两份结论最初由 Claude Code 根据简历和上级 `CLAUDE.md` 生成，现已做编辑整理，删去重复表述和没有简历依据的推断。评分沿用本仓库的示例口径，不代表通用招聘标准。

复现本组示例时，以入库日期 **2026-08-20** 为评估基准，解释简历里的“至今”和“近两年”。真实筛选使用实际评估日期，并在结论中注明。

独立试跑时先读 PDF、岗位和流程说明，生成自己的结论后再查看参考答案，避免答案影响判断。

王五简历的 2020.07–2021.05 项目按通用推理服务网关描述；技术栈中单独列出的框架，不作为该早期项目使用过它们的证据。试跑时应核对技术与项目时间线，不为了贴合参考结论补全经历。

## 试跑

在仓库根目录向 AI 助手说明：

```text
读取 resume-screening/CLAUDE.md，使用示例岗位和评分口径，筛选 resume-screening/examples/resume_王五.pdf。
```

对照时检查项目证据、岗位边界和待确认项。结论不同，应先检查输入、适用口径和推理依据，再判断说明是否需要修改；无需追求逐字一致。
