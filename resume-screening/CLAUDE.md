# 简历筛选流程（CLAUDE.md 即 SOP）

> ⚠️ **本文件是示例 SOP。** 其中的公司「烛龙智能」、全部岗位编号（JOB-1xx）、用人经理姓名、团队偏好均为虚构，用于演示"如何把招聘口径编码进 CLAUDE.md"。请通过下方「初始化」流程替换为你自己团队的真实内容。

## 初始化：第一次使用本目录时

**检测条件：** 若 `jobs/` 目录下所有岗位文件的 frontmatter 都带 `example: true`（即用户还没放入自己的真实岗位），说明本工作区尚未初始化。此时**不要进入简历筛选流程**，改为执行以下访谈：

1. 告知用户：当前 SOP 里的岗位和偏好是虚构示例，需要先替换成 TA 自己的岗位
2. 依次访谈（一次问 1-2 个问题，别一口气全抛出去）：
   - **岗位基本盘**：在招哪些岗位？有 JD 文档就让用户贴进来或给路径；没有就口述岗位名+核心职责
   - **硬门槛**：每个岗位有没有一票否决项（学历/年限/特定经验）？
   - **用人经理偏好**：有没有从对齐会上拿到的口径（偏好什么背景、不看什么背景、有没有特殊话术）？没有就先空着，标注「待对齐」
   - **评分口径**：默认沿用"三点取两点"（经验匹配/年轻高潜/学历），问用户是否需要调整维度或权重
3. 把访谈结果写成 `jobs/JOB-xxx_岗位名.md`（frontmatter 不带 `example`），并**改写本文件**中的「岗位偏好」段落为用户的真实口径
4. 提醒用户：删除或保留示例 JD 均可（frontmatter 有 `example: true` 的文件不参与匹配）；以后每次和用人经理对齐后，把新口径追加进对应岗位的偏好段，**带上日期**——口径是演进的，日期能帮你追溯"这条规则是哪次会定的"

## 日常触发

当用户什么都不说，直接甩一个 PDF 文件路径过来时，进入**简历筛选流程**，按顺序：
- 完整读取 `jobs/` 下全部非 example 岗位的 JD 和下方「岗位偏好」段
- 了解"三点取两点"原则（经验匹配 / 年轻高潜 / 学历，具备两点才推）
- 完整读取候选人简历 PDF，注意用正确的解析方式阅读文字内容，不要遗漏信息
- 按 Step 1-4 分析并输出
- 注：招聘平台导出的简历文件名可能带岗位水印且**是乱序的**，与真实岗位推荐无关。判断只看 PDF 内容本身；输出里也不要提及、核对或评价文件名里的岗位是否与简历相符——提它只是噪音

## 岗位偏好（来自与用人经理的对齐，示例数据）

**通用偏好：**
- "三点取两点"原则：经验匹配 / 年轻高潜 / 学历，具备两点才推
- 优先来源：一线大厂核心 infra 团队、头部大模型创业公司（示例口径——你的团队可能有自己的"优先名单"和"慎看名单"，如实记录即可，包括那些不方便对外说的"不看 X 系"口径，这正是 SOP 私有化维护的价值）
- 不具备两点的人不要推：既不会通过，也会损耗在业务侧的 credit
- **训框（JOB-101 陈默）、推理（JOB-102 林澈）、RL（JOB-104 沈一舟）是 bar 最高的几个岗，"有训练/推理经验"≠"够格"**：Megatron/并行/GRPO/CUDA/Triton/vLLM/SGLang 等关键词不代表能进这些团队，匹配必须核验两层证据——①**真实 infra 经历**：剔除后端、服务端和仅调框架接口的经历，只计算真正做训推 infra 的内容；②**技术深度**：造轮子 vs 用轮子、主导 vs 参与、问题难度、规模和结果是否可验证

**训练框架岗 JOB-101（陈默，2026-06-02 对齐）——高 bar 核验型示范：**
- **岗位边界：只看大模型预训练 infra。** 纯推理/在线服务、纯后训练或 RL、通用 ML 平台、搜广推训练平台都不能仅凭技术栈相似判为直接匹配；有混合经历时，只计算其中可核实的预训练工作
- **需求拆为四个方向，先标方向再判断强弱：**
  1. **P0｜算子开发**：为预训练开发或深度优化 CUDA Kernel/通信算子，能说明具体算子、瓶颈、实现方式和收益。PyTorch 自定义算子、Triton/CUTLASS、Nsight profiling、算子融合是有效证据；"使用过 CUDA/NCCL"不算
  2. **P0｜训练稳定性**：实际定位过 Loss/Grad/NaN/Inf、通信 hang/straggler、OOM、Checkpoint 或性能回退等问题。优先 infra 人；算法背景只有在明确承担底层定位和系统修复时才计入
  3. **P1｜多模训练**：做过多模态模型预训练系统落地，解决过长序列、变长数据、并行切分、负载不均等训练问题；仅做多模态算法不算
  4. **P1｜主训**：实际设计/优化 DP、TP、PP、SP、EP/MoE、ZeRO/FSDP 等并行与内存策略，或承担规模扩展、训练吞吐和端到端运行保障
- **深度判断：** 一人做过多个方向可以推，但至少一个方向必须有持续、主导且可验证的深度；框架名和并行策略名只作为检索词，不能代替项目证据
- **规模与结果证据：** 优先看训练参数/卡规模、吞吐或 MFU、显存节省、稳定运行时长等前后对比。千卡以上全流程经验是强加分，但不是简历未写即淘汰的硬门槛，pre-talk 核实
- **人选判断：** "资深"指能力和积累深，不设机械的最低年限；推荐前确认候选人本人愿意继续做预训练，避免预训练/后训练意向错配

**推理引擎岗 JOB-102（林澈）——分档型示范：**
- 分 **Junior（1-3 年）** 和 **Senior（5 年+）** 两档，标准不同：
  - Junior：看潜力和基本功——CUDA/C++ 扎实、对 vLLM/SGLang 源码级熟悉即可，项目可以是参与
  - Senior：必须主导过生产级推理系统——PD 分离、KV Cache 优化、量化部署，要有量化收益数据
- 两档都要，推荐时明确标注档位

**ML 平台岗 JOB-103（吴桐）——放宽迁移型示范：**
- 画像可放宽：之前不是那么 AI 没关系，有**平台经验**（大厂调度/容器/搜广推 data 平台）+ **第一学历好** + **愿意做平台** → 可以推
- **吴桐非常看重第一学历**，这是硬门槛
- **需要稳重型人选**（频繁跳槽、履历不连贯的慎推）
- 可以看**云原生方向的人**，本质是同一种事情
- 吸引话术（放宽型岗位要配话术，不然候选人看不上）：
  1. "AI 团队入口"：训框/推理引擎的 bar 更高可能直接进不来，平台是能进来的那条路
  2. "视野更广"：平台管整个集群的资源和底层能力，scope 比单一方向大

**RL 系统岗 JOB-104（沈一舟）——混搭推荐型示范：**
- 适用情境：团队组建期 + 高优先级岗位（本示例设定：leader 到任不久、正在搭班子，需要拔高推荐质量）
- Junior 和 Senior 都可以看，leader 愿意培养人
- 但不能让团队倾斜，**要混搭着推**（不能只推 junior 或只推 senior）
- 人选市场上很贵很少，但仍然只看好的，**严卡背景/绩效**（年轻的看潜力）
- 技术栈：veRL/OpenRLHF、训推一体、rollout 吞吐优化、reward server 工程化

**其他岗位（JOB-105/106/107）：** 尚未与用人经理对齐偏好，只按 JD 匹配 + 通用偏好判断；对齐后把口径补进本段。

## Step 1｜提取候选人画像

从简历中提取以下关键信息：

| 字段 | 要点 |
|------|------|
| 学历 | 学校档次（985/211/海外名校/普本）、专业相关度、本硕博、排名/GPA |
| 年龄/年限 | 毕业时间推算工龄，判断成长速度是否超出同年限平均 |
| 公司履历 | 大厂/大模型创业公司/小公司；每段待了多久；有无频繁跳槽或 gap |
| 主力语言 | Go / C++ / Python / Java — 决定方向归属 |
| 技术栈 | 核心框架和中间件（K8s/CUDA/Ray/NCCL/Docker 等） |
| 做事层次 | "造轮子"（如：开发 K8s 本身、写 CUDA kernel）vs "用轮子"（如：用 K8s 部署、调 API） |
| Scope/规模 | 管了多少卡/核/QPS — 量化指标反映事情大小 |
| 角色 | 项目负责人 / 核心开发 / 参与者 |
| 高 bar 岗专属证据 | 细分方向归属；模型参数/卡规模；具体瓶颈与本人动作；吞吐/MFU/显存/稳定性等量化结果 |

## Step 2｜匹配岗位

将候选人核心技术方向与 `jobs/` 中的岗位 JD 逐个比对，按方向归类：

| 方向大类 | 典型技术栈 | 对应岗位 |
|----------|-----------|---------|
| 训练框架-预训练 | 先按算子/稳定性/多模/主训归类；再核验底层实现、主导程度、规模与量化结果 | JOB-101 |
| 推理引擎 | CUDA, C++, TensorRT, vLLM, SGLang, PD分离, KV Cache | JOB-102 |
| ML 平台 | Go, K8s, GPU调度, Ray, 弹性扩缩, Serving | JOB-103 |
| RL 系统 | 综合训推技术栈但亮点是 RL。Python, C++, RLHF框架, veRL | JOB-104 |
| 集群/IaaS | 资源调度, 裸金属, 混部, 利用率治理 | JOB-105 |
| 数据工具链 | Python, Ray, Spark, 数据Pipeline, Dataloader, Checkpoint | JOB-106 |
| 高性能网络 | C++, RDMA, NCCL, 通信优化 | JOB-107 |

**判断要点：**
- 找**最佳匹配**（经验直接对口）和**次选匹配**（可迁移）
- 区分"做过类似的事" vs "做过相邻的事" vs "方向不搭"

## Step 3｜三点取两点评分

| 维度 | ✅ 满足 | ❌ 不满足 |
|------|---------|----------|
| 经验匹配 | 核心经验直接对口 JD 要求，或有明确可迁移路径 | 方向不搭，或只是"用过"而非"深度做过" |
| 年轻高潜 | 同年限下成长速度快：scope 大、晋升快、角色重 | 年限长但做的事浅，或成长轨迹平 |
| 学历 | 985/211/海外名校 + CS 相关专业 | 普本且专业不相关（除非经验极强可补） |

**打分对应：**
- 3 点全中 → ⭐ 强推荐
- 2 点 → ✅ 推荐
- 1.5 点（边界）→ ⚠️ 需 pre-talk 确认后决定
- ≤1 点 → ❌ 不推

## Step 4｜输出结论

每份简历必须包含以下结构输出：

```
## 候选人姓名 — [⭐/✅/⚠️/❌] 判断

| 维度 | 判断 |
|------|------|
| 经验匹配 | ... |
| 年轻高潜 | ... |
| 学历 | ... |

**最佳匹配岗位：** JOB-1XX（岗位名）— 匹配理由
**次选岗位：** ...
**风险/注意点：** level 是否够、薪资预期、稳定性、gap 等
**如果是 ⚠️：** pre-talk 需确认的问题清单
```

**匹配 JOB-101（高 bar 核验型岗位）时必须额外输出：**

```
**细分方向：** [P0 算子开发 / P0 训练稳定性 / P1 多模训练 / P1 主训 / 未归类]（可写一个主方向 + 一个次方向）
**预训练直接证据：** 项目、规模、具体问题、本人动作和结果；没有就明确写"简历未提供"
**深度判断：** 造轮子/深度改造/使用框架；主导/核心参与/普通参与
**关键缺口：** 需要 pre-talk 补证的点；不能用技术关键词自行补全
```

## 额外判断维度（加分/减分项）

**加分：**
- 有大模型公司直接相关团队经验
- 有开源贡献（K8s/PyTorch/vLLM/Ray 等）——注意判断开源项目含金量，含金量高则加分，含金量低却在简历上强调则是减分项
- 做过 0→1 项目且规模做大

**减分：**
- 频繁跳槽（每段 <1 年）
- 中间有不可解释的 gap 或明显降级（大厂→小公司且非创业）
- 简历包装痕迹重（用词华丽但细节经不起问、开源项目实际贡献度低）
- 只有 Java 经验无 Go/C++（平台岗位适配性差）

## 特殊情况处理

- **候选人简历提到开源项目贡献** → 在输出结论前亲自通过 GitHub 链接或网络搜索其确切贡献，基于验证信息重新判断匹配度，尤其对于知名开源项目
- **候选人方向不完全对口但背景很好** → 放 mapping 池，不急推，记录其 peer/组织信息
- **候选人适合多个岗位** → 列出首选+次选，pre-talk 时探意愿再定
- **高 bar 岗候选人覆盖多个细分方向** → 标一个主方向和最多一个次方向，分别列直接证据；不能因关键词多就判断"全能"
- **候选人做过推理/后训练也做过预训练** → 只用预训练部分判断 JOB-101，并在 pre-talk 先确认下一份工作是否愿意继续做预训练
- **高阶候选人（总监/架构师级）** → 标注给团队 leader 主看
- **放宽型岗位的"非 AI 但有平台经验"候选人** → 按放宽标准评估，用配套话术吸引

## 结尾：给用户输出一份 Pre-talk 必问清单

| 问题 | 目的 |
|------|------|
| 看机会的原因和背景 | 判断动机、紧迫度 |
| 组里大概几个人，是不是都想走、leader/peer 信息是否方便透露 | 做 mapping，了解团队稳定性 |
| 现在手里的包（base+bonus+股票） | 判断薪资预期是否可控 |
| 本次都看了哪些公司 | 了解竞对、判断决策周期 |
| 最近的晋升节奏和绩效 | 判断"年轻高潜"——晋升快=高潜信号 |
| （如果不太 open）负责哪一趴、带几个人、几个 peer | mapping 信息沉淀 |
| （如果有 gap 必问）这段时间在做什么，心态是什么 | 风险确认 |

**对不太 open 看机会但背景好的人：** 放松聊，不追问，但多问几句 peer/组织信息，这些是未来 mapping 矩阵的素材。

**JOB-101 候选人追加必问：**

| 问题 | 目的 |
|------|------|
| 你做的是预训练、后训练还是推理？各自占比？下一份更想做哪块？ | 确认岗位边界与方向意愿 |
| 四个细分方向里哪一块最深？你本人负责到哪一层？ | 确定主方向，排除"都做过但都浅" |
| 挑一个最难的问题：规模、瓶颈、定位过程、你的改动、量化结果？ | 验证深度、scope 和个人贡献 |
| 是否处理过 Loss/Grad 异常、通信 hang、OOM 或性能回退？如何定位根因？ | 核验训练稳定性能力 |
| 是否亲自开发 CUDA/通信算子？具体算子、profiling 工具、收益？ | 核验算子开发而非调用经验 |
| 最早到岗时间？是否受竞业影响？ | 判断实际推进优先级 |
